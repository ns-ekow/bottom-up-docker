Question

Section titled “Question”

What is a process, what does the kernel give it, and why is PID 1 special?

Every container is, underneath, a group of ordinary processes. Before we can isolate them (module 03) or limit them (module 05), we need to know what a process is and how one starts and ends. We also need to know what goes wrong when the first process in a container doesn’t do the jobs the kernel gives it.

Build

Section titled “Build”

Write bud-init: a minimal PID 1 for bud, in Go. Run as bud-init -- <command>, it must:

  1. start the command and forward SIGTERM, SIGINT, SIGHUP, SIGQUIT, SIGUSR1 and SIGUSR2 to it;
  2. when SIGCHLD arrives, reap every finished child, not only the command, because orphans in the namespace are adopted by PID 1;
  3. when the command ends, exit with its status: its exit code, or 128 plus the signal number if a signal killed it.

Start from labs/m01-processes/starter/bud-init/main.go. Remember rule 2 above: as PID 1, your program only receives the signals it has handlers for, so asking Go for them (signal.Notify) is what makes forwarding possible at all.
